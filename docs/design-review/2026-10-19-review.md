- 사용자 요청은 두 GNOME 앱의 디자인/상호작용 검토, Mac의 작은 상태 창에서 참고할 원칙 찾기, REA 검토, 바깥 우클릭 닫기, PNG 증거 저장, 두 GitHub 저장소 업데이트다.
- 코드 검토는 `/home/k/workspace/arch/archsport`와 `/home/k/workspace/arch/matci`의 `AGENTS.md`와 Linux 인수인계 문서, 구현 계획, 현재 GJS/CSS/순수 모델/검증 파일을 기준으로 했다.
- 사용자가 제공한 화면 조각은 [원본 캡처](user-crop-2026-10-19.png)로 보존했다. 파일 크기는 173×206 px다. 날짜 문자열이 오른쪽 crop 끝에서 잘리고 정보 아이콘이 아래 모서리에 붙어 보이지만, 캡처 테두리 밖의 화면을 볼 수 없어 이것이 실제 앱 레이아웃의 잘림인지 crop 자체의 경계인지는 확정할 수 없다.
- [PNG 검토 보드](notch-ui-audit.png)는 원본 조각과 소스에서 재현되는 문제, 변경 방향, 확인하지 못한 범위를 한 장에 모았다. 원본 캡처는 보드를 위해 수정하지 않았다.
- REA 정적 소스/AST 검토는 실제 GJS 코드의 신호·actor·shared coordinator 경로를 교차 확인하는 데 썼다. 네이티브 Mach-O 중심 runtime-inspector는 GJS 화면에 맞지 않아 실행하지 않았다. 확인 근거 식별자: Archsport `ev_791b4799719d6395ede826da166e65780266dcd9c737d030a3c3a023078caa35`, parent `ev_6b428f0796c6014ac6406941130d214d59e5ce4c3a18b71d4be7c30a15f94aef`; matci `ev_2bfab84c09e2db66f63c6a1d2a3385bdc7ec8e48cb3964ef129a10e15893ece0`. 이 증거는 코드 구조 검토지 GNOME 실행 증거가 아니다.
- 병렬 감사는 Archsport 긴 내용/글자 밀도, matci dispose 뒤 actor 접근, 공유 stage 입력 전달, 마지막 diff의 동작/문서 범위를 별도로 검사했다. 교차 리뷰에서 발견한 trigger 판정 키 mismatch와 “다른 앱 패널 아이콘 클릭도 바깥 클릭이어야 한다” 권고를 반영하고, owner/outside 조합 테스트를 추가했다.

## 확인된 문제와 반영

| 문제 | 확인 근거 | 코드 반영 |
|---|---|---|
| Archsport 긴 일정/최근 경기 내용이 고정 높이에서 잘릴 수 있음 | 기존 GJS가 확장 내용을 직접 세로 배치하고 370 px로 제한 | 고정 헤더와 `St.ScrollView` 본문으로 분리. 모니터 높이와 패널을 고려해 최대 520 px 안에서 본문 높이를 계산하고 넘치는 목록은 스크롤 |
| 다른 앱을 눌러도 열린 노치가 남음 | 두 확장에 공유 outside-pointer 감지가 없음 | shared dock protocol 3에 stage capture 한 개를 두어 열린 소유자의 노치 바깥 좌·우클릭만 닫기로 처리. 가운데·4·5번 버튼은 무시. 소유자 패널 버튼과 자기 노치 내부 입력만 예외. 다른 확장 패널 버튼은 닫힘 대상 |
| 닫을 때 패널이 즉시 사라져 상태 전환이 거침 | 공유 dock 숨김은 즉시 `visible=false` | 열기 220 ms, 닫기 170 ms opacity/scale easing. 기존 위치·크기 320 ms 동작은 유지. GNOME `enable-animations` 설정을 따르고 Shell 종료 시 전환 생략 |
| 점수 변경 애니메이션이 글자를 과하게 키움 | Archsport 점수 label에 scale transition 사용 | 점수는 opacity와 4 logical px 이동 240 ms, 사건 행은 220 ms로 변경 |
| matci dispose된 위젯/패널에 worker callback이 접근할 위험 | 2026-10-19 01:35 KST 종료 로그의 matci v8 dispose 이후 UI update stack 및 이전 shared-dock 종료 경고 | `Main.panel`, root, indicator, stage 종료 경계에서 두 앱의 Shell-ending guard를 먼저 올리고 worker/timer/shared capture를 정지. 종료 후 render/visibility/update 경로 차단. 일반 확장 비활성화는 기존 정리 경로 사용 |
| 작은 상태 텍스트 대비/크기와 버튼 press 구분이 약함 | 스타일시트의 9–11 px 보조 텍스트와 약한 active 상태 | 두 UI의 보조 글자/상태 레이블을 가독성 높게 조정하고 버튼에 pressed 상태 추가 |

`matci` 바깥 클릭은 펼친 표면을 닫되 검토 선택을 유지한다. captured handler는 클릭을 소비하지 않고 `Clutter.EVENT_PROPAGATE`를 반환해 대상 앱/패널 메뉴가 입력을 계속 받게 한다.

공유 coordinator source hash에는 layout/ownership/hit-test 판정, GI 버튼 반환값 정규화와 1/3 버튼 필터, event 좌표 처리, actor 전환 함수, capture dispatcher와 `DockParticipant` 구현을 포함했다. 서로 다른 사본을 GNOME 세션 안에서 섞어 로드하면 source hash 경고가 나도록 했다. 저장소 사본 자체는 byte-for-byte 검사도 통과했다.

## Mac 유사 UX 참고 범위

macOS Dynamic Island / Live Activities의 작은 상태 요약과 필요할 때 확장되는 정보 계층, popover의 바깥 클릭, 짧고 상태 변화를 돕는 motion을 참고했다. GNOME 앱은 시스템 패널 아래 `affectsStruts:false` overlay로 구현하므로, macOS 전용 하드웨어 노치나 원본 애니메이션을 복제한 것으로 표현하지 않는다. 실제로는 기존 창의 좌표를 예약하지 않도록 하고, 사용자 입력과 모션 감소 설정을 존중한다.

- [Apple HIG: Popovers](https://developer.apple.com/design/human-interface-guidelines/popovers)
- [Apple HIG: Motion](https://developer.apple.com/design/human-interface-guidelines/motion)
- [Apple HIG: Live Activities](https://developer.apple.com/design/human-interface-guidelines/live-activities)
- Mint for Mac과 Apple Sports는 저장소의 참조 목록/사용자가 보낸 이미지로 정보 위계와 아이콘 사용만 확인했다. 사용되지 않은 비공개 앱 코드나 로고는 가져오지 않았다.

## 버전과 검증

- Archsport source metadata: v12. matci source metadata: v9. 두 저장소의 `notchDock.js`와 `dockModel.js`는 동일해야 하는 shared 파일이며 바이트 일치 검사를 했다.
- 설치 실행본은 점검 시 Archsport v11, matci v8, GNOME Shell 50.1, 두 확장 `ACTIVE`였다. 새 소스 v12/v9는 이번에 GitHub에 올리며, 작업 중 GNOME 확장을 reload하거나 사용자 로그아웃하지 않았다.
- Archsport: Python 65/65, Node 11/11, schema strict dry-run, GJS 파일 Node syntax parse, demo one-shot 통과. ESLint 9 오류 0, 경고 39개(미사용 catch 매개변수).
- matci: Python 51/51, Node 26/26, schema strict dry-run, planning artifact 검증, GJS 파일 Node syntax parse 통과. ESLint 9 오류 0, 경고 38개(미사용 catch 매개변수).
- 두 저장소 `git diff --check` 통과. 순수 Node 모델 테스트는 hit-test 조건, 이벤트 종류, 소유권, 스크롤 높이를 확인하지만 GJS actor나 Shell native event dispatcher를 실행하지 않는다.

## 남은 실기 검수

- GNOME 50.1에서 실제 stage captured-event 좌·우클릭 닫기, 가운데·측면 버튼 무시, 앱/패널 메뉴 입력 전달, 현재 소유자/다른 앱 아이콘 예외를 확인하지 않았다. Node 순수 모델은 1/3만 닫고 2/4/5는 유지함을 검증한다.
- v12/v9 코드의 실제 모션, 듀얼 앱 배치, 좁은 화면, 125/150% 배율, 긴 경기 목록, 전체 화면/overview 전환은 아직 시각 검수 전이다.
- 종료 경계 코드는 테스트했지만 새 버전에서 실제 Shell 종료를 수행하지 않았다. 이전 GNOME dispose 로그가 새 버전에서 사라졌는지는 아직 확인하지 않았다.
- 원본 173×206 crop만으로 날짜 줄의 실제 UI clipping 여부를 판단할 수 없다.

로그아웃하면 열려 있는 데스크톱 앱이 종료된다는 사용자 제약을 따라, 이번 작업에서 로그아웃/재로그인이나 GNOME 재시작은 하지 않았다.
