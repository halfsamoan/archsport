# Archsport 컴포넌트·노치·모션 규격

사용자 환경: **ASUS Vivobook 15 Pro, Ubuntu GNOME**. 일반적인 직사각형 디스플레이에 가상 노치를 표시한다. 정확한 SKU, 패널 해상도, OLED 여부는 확인하지 않았고 가정하지 않는다. 이 문서의 치수는 물리 픽셀이 아닌 논리 픽셀이다.

## 시각 방향

작업 중에는 검정 표면에 점수만 남기고, 클릭·중요 사건이 있을 때 같은 표면이 커진다. 축구 점수판의 중앙 정렬과 데스크톱의 차분한 문맥을 결합했다. Apple 글꼴·팀 로고·아이콘을 추출하지 않았다. 사용자 추가 요청으로 구단 식별은 API-Sports 미디어의 실제 Barcelona/Inter PNG로 변경했고, 실제 상대도 팀 ID의 로고를 캐시한다. 배경 풍경은 코드로 만든 독자 벡터다.

토큰: `tokens.json` / `tokens.css`. 시스템 sans-serif와 tabular 숫자 사용. 웹 전체 데모는 축소된 데스크톱을 보여주므로 일부 설명은 8–10px로 표현했다. **실제 데스크톱 배포판은 최소 12px caption / 14px body**를 기준으로 확대해야 한다. 토큰 대비 검사는 주요 텍스트 조합에 한정하며 웹 전체 모든 장식 색·작은 글자의 접근성 검증을 대체하지 않는다. Tailwind를 쓰지 않아 무의미한 Tailwind 설정 파일은 만들지 않았다.

## 표면

| 상태 | 크기 | 내용 | 진입·종료 |
|---|---|---|---|
| compact | GNOME 280×46 | 양 팀 로고·점수·분/상태 | 진행 경기와 새 사건에서만 표시. 클릭/Enter/Space로 펼침 |
| expanded | GNOME 최대 520×모니터 가용 높이 | 고정 헤더·점수·스크롤 가능한 일정/최근 경기/스탯 | 아래 본문만 스크롤. 상단 패널과 모니터 경계 안에 유지 |
| event | GNOME 최대 520×180 | 득점/정정/상태 변화·변경 점수 | 새 중요 사건을 짧게 표시한 뒤 compact; 수동 화면은 유지 |
| offline | 기존 크기 | 마지막 데이터·연결 상태 | 최신 값 도착까지 유지 |
| no match | compact/expanded | 오늘 경기 없음 | 가짜 점수나 오래된 경기를 라이브로 표시하지 않기 |

웹은 위 3크기를 적용한다. GNOME 너비는 모니터 폭−24 논리픽셀 안으로 제한한다. 펼친 노치는 패널 바로 아래 오버레이이며 `affectsStruts:false`로 작업영역을 바꾸지 않는다. 노치 빈 배경은 클릭을 통과시킨다. 펼친 영역 밖의 버튼 누름은 우클릭을 포함해 접되, 클릭 이벤트는 원래 앱·메뉴까지 전달한다. 현재 소유 노치의 실행 아이콘만 예외이며, 다른 확장 아이콘은 바깥 클릭으로 처리한다. GNOME에서 HTML의 픽셀 완전 일치나 날개 곡선까지 구현 완료했다고 주장하지 않는다.

위쪽 가장자리 0px, 아래 모서리 20/30px. 웹 날개는 폭 18px의 오목한 radial mask로 형성한다. 노치 배경은 불투명하여 뒤 작업창 내용이 점수와 섞이지 않는다. 본문은 흰색, 상태는 민트, 오류/지연은 황색과 텍스트를 함께 쓴다. 색만으로 live/offline을 구별하지 않는다.

## 동작과 애니메이션

| 변화 | 목표 | 타이밍 | 구현 및 제한 |
|---|---|---|---|
| compact/hidden → expanded | 상단 패널 아래에서 graphite 표면이 열림 | GNOME 크기 280ms + opacity/subtle scale 230ms | Clutter EASE_OUT_CUBIC, 모션 설정을 따름 |
| expanded → hidden | 투명도와 세로 크기를 줄여 접힘 | 165ms | 다른 창·패널 입력은 차단하지 않고 원 이벤트 전달 |
| 내용 등장 | 글자 왜곡 없이 사건 정보 표시 | 점수/사건 행 210/190ms | 텍스트를 확대하지 않고 opacity·짧은 y 이동만 사용 |
| expanded → compact | 정보 밀도 감소, compact 상태 유지 | GNOME 크기 280ms | compact 라이브 경기는 접은 뒤에도 표시 |
| 골 | 사건을 알아볼 정도의 한 번 반응 | 웹 배지 600ms, GNOME 텍스트 이동 | 한 번만. 깜빡임·무한 맥동·폭죽 없음 |
| 자동 접힘 | 방해 최소화 | 수신/시연 후 6000ms | 이전 timer 취소, 새 이벤트가 최신 timer 소유 |
| 모션 감소 | 정보 유지, 큰 움직임 제거 | 0ms 크기 변화 | 웹 prefers-reduced-motion 및 설정; GNOME enable-animations |

실제 Apple spring 수치를 알아냈다는 뜻이 아니다. 구현한 웹 easing은 물리 spring이 아니다. M3에서는 위치·크기 전이를 중간 상태에서 반전시키고, 이벤트가 전이 도중 도착해도 최신 목표로 이어지는지 검수한다. GNOME ease는 Clutter의 별도 곡선을 사용한다.

## 재사용 컴포넌트

**NotchSurface** — compact/expanded/event/offline. 웹은 role=button, tabindex, Enter/Space/Escape, aria-expanded, 시연 경기를 알리는 이름. 상세 버튼의 클릭은 외곽 토글에 전달하지 않는다. 제품 단계에서는 외곽 button 역할과 내부 버튼의 중첩 의미를 피하도록 패널과 토글을 분리할 것.

**ScorePair** — null은 `–`, 0은 `0`. 홈/원정 순서 유지. 득점 여부를 서버에 없는 선수 정보로 꾸미지 않는다. 정규·연장 점수와 PK 점수를 별도로 표시. 현재 웹은 고정 시연 스코어, native PK 표시는 후속.

**TeamMark** — 실제 공급사 구단 로고. 원본 비율을 유지하고 contain으로 표시한다. 로고가 없거나 다운로드에 실패하면 평문 팀 이름을 보여준다. 임의 구단 마크를 생성하지 않는다. 긴 상대 이름은 줄임표와 접근 가능한 전체 이름 병행. 원본 URL·SHA256은 manifest에 기록한다.

**EventRow** — 분, 사건명, 팀, 선수. 제공자 값이 없으면 단정하지 않는다. 교체와 골을 같은 말로 표현하지 않는다. 정정은 성공색만 쓰지 않고 ‘정정’이라고 명시.

**SegmentButton** — 선택/기본/hover/pressed/focus. selected는 배경과 글자 두 신호. 포커스 링 3px, offset 4px. 시제품 버튼은 실제 상태 전환을 수행.

**Dialog** — 네이티브 HTML dialog. 열면 focus 이동, Escape 닫기, 닫기 버튼, 배경 클릭 닫기, 스크롤 유지. 설정은 브라우저 localStorage에 저장. OS 설정으로 동기화되는 것처럼 표시하지 않음.

**DataHealth** — demo/live/error/idle. demo에서는 ‘시연’ 명시. live라도 최신 수신 시간과 갱신 지연이 보이도록 제품 확장 필요. 오래된 값을 live dot으로 계속 강조하지 않는다.

## 검수 시나리오

1. compact 클릭 → expanded, 빠른 재클릭 → compact. 점수 글자가 찌그러지지 않음.
2. 펼친 노치 밖의 좌·우클릭은 노치를 접고, 컨텍스트 메뉴와 원래 클릭 대상을 정상 작동시킴. 현재 소유 아이콘 안쪽만 보호하며 다른 앱 아이콘 클릭은 접음.
3. 긴 경기 목록은 헤더를 고정하고 본문만 스크롤, 일정 안내까지 휠·키보드로 도달.
4. 득점 버튼 → event 2:1, 자동 6초 접힘, 이후 2:1 유지.
5. 이벤트 도중 수동 접기 → 이전 timer가 새 펼침을 나중에 닫지 않음.
6. 오프라인 시연 → ‘연결 끊김’·마지막 정보. 복구 시 중복 골 알림 없음.
7. 모션 감소 → 0ms, 스포일러 설정 → 점수 가림 및 득점 시연 차단.
8. 키보드만으로 노치·설정·팀 검색·상세 닫기 가능.
9. 390px 폭·1366px·1520px, 텍스트 확대 200%에서 가로 문서 스크롤·노치 이탈 없음.
10. Ubuntu 실기기의 125/150/200% 배율 및 60/120Hz frame time은 별도 실측. ASUS의 화면 스펙을 추측해 통과 처리하지 않음.
